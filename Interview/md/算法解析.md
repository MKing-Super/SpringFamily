### quiz03

题目：

```
设定一组四码的数字作为谜底，另一方猜每猜一个数，出数者就要根据这个数字给出提示，提示以XAYB形式呈现，直到猜中位置。

其中X表示位置正确的数的个数(数字正确且位置正确)，而Y表示数字正确而位置不对的数的个数例如，当谜底为8123，而猜谜者猜1052时，出题者必须提示0A2B。例如，当谜底为5637，而猜谜者猜4931时，出题者必须提示1A0B。当前已知N组猜谜者猜的数字与提示，如果答案确定，请输出答案，不确定则输出NA。

输入描述
第一行输入一个正整数，0< N < 100.
接下来N行，每一行包含一猜测的数字与提示结果

输出描述
输出最后的答案，答案不确定则输出NA。

示例1：
输入
6
4815 1A1B
5716 0A1B
7842 0A1B
4901 0A0B
8585 3A0B
8555 2A1B

输出
3585
```

**解题思路**

这是一个经典的 **Bulls and Cows（猜数字）** 逆推问题，核心是：**枚举候选答案 → 用所有历史提示去过滤 → 看剩下的候选是否唯一**。

1. 枚举空间

谜底是一个 4 位编码，每一位是 `0~9`，且允许数字重复（本题答案 `3585` 就重复了 `5`）。因此可以枚举 `0000` 到 `9999`（共 10000 个），格式化成 4 位字符串处理；如果题目保证是“不含前导零的四位数字”，枚举 `1000~9999` 也可以，本例结果一致。

2. 如何正确计算 X A Y B（易错点）

给定候选 `cand` 和猜测 `guess`：

- **A（位置正确的个数）**：逐位比较，`cand[i] == guess[i]` 的个数。
- **数字正确的总数（含位置正确的）**：对 `0~9` 每个数字 `d`，取它在 `cand` 中出现次数与在 `guess` 中出现次数的**较小值**，求和。
- **B（数字正确但位置错误）**：`数字正确总数 - A`。

> ⚠️ **绝对不能**用 `Set` 或“逐个去另一个串里找”的方式算 B，否则遇到**重复数字**（如本题的 `5`、`8` 多次出现）会算错。必须用“计数取 min”的方法。

3. 判定

- 把每一条 `(guess, XAYB)` 都拿来检验候选，只有**全部满足**的候选才保留。
- 最后：
  - 恰好剩下 **1 个** → 输出它（答案确定）；
  - 剩下 **0 个或多个** → 输出 `NA`。

------

**完整 Java 参考实现**

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = Integer.parseInt(in.next());

        List<String> guesses = new ArrayList<>();
        List<int[]> hints = new ArrayList<>(); // 每个元素为 {A, B}

        for (int i = 0; i < n; i++) {
            String g = in.next();          // 猜测的4位数字，如 "4815"
            String hint = in.next();       // 提示，如 "1A1B"
            int a = hint.charAt(0) - '0';  // X
            int b = hint.charAt(2) - '0';  // Y（格式固定为 X A Y B）
            guesses.add(g);
            hints.add(new int[]{a, b});
        }

        List<String> candidates = new ArrayList<>();
        // 枚举所有 4 位编码：0000 ~ 9999（若限定无前导零，改为 i<=9999 && i>=1000 即可）
        for (int i = 0; i <= 9999; i++) {
            String cand = String.format("%04d", i);
            boolean ok = true;
            for (int j = 0; j < n; j++) {
                if (!match(cand, guesses.get(j), hints.get(j)[0], hints.get(j)[1])) {
                    ok = false;
                    break;
                }
            }
            if (ok) {
                candidates.add(cand);
            }
        }

        // 唯一则输出，否则输出 NA
        if (candidates.size() == 1) {
            System.out.println(candidates.get(0));
        } else {
            System.out.println("NA");
        }
        in.close();
    }

    /**
     * 判断候选答案 cand 面对猜测 guess 时，是否得到 aAbB
     */
    static boolean match(String cand, String guess, int a, int b) {
        int A = 0;
        int[] cntC = new int[10]; // cand 中各数字出现次数
        int[] cntG = new int[10]; // guess 中各数字出现次数

        for (int i = 0; i < 4; i++) {
            char c = cand.charAt(i);
            char g = guess.charAt(i);
            if (c == g) {
                A++; // 数字和位置都对
            }
            cntC[c - '0']++;
            cntG[g - '0']++;
        }

        int total = 0; // 数字正确的总数（位置对 + 位置错）
        for (int d = 0; d < 10; d++) {
            total += Math.min(cntC[d], cntG[d]);
        }
        int B = total - A; // 数字对但位置错

        return A == a && B == b;
    }
}
```

### quiz01

```
小明有n个可选运动，每个运动有对应卡路里，想选出其中k个运动且卡路里和为t。k，t，n都是给定的。求出可行解数量

```

思路：**回溯算法（Backtracking）/ 深度优先搜索（DFS）**

解题思路

核心思想：决策树 + 回溯

把每个运动看作一个决策点：**选它** 或 **不选它**，构成一棵二叉决策树。

```
第 index 个运动：
  ├─ 不选 → 进入 index+1，selected 不变，sum 不变
  └─ 选   → 进入 index+1，selected+1，sum + calories[index]
```

走到叶子（处理完所有 n 个运动 / 或超过约束）时检查是否恰好选了 k 个且 sum == t。

状态定义

```
dfs(index, selectedCount, currentSum)
```

- `index`：当前考虑到第几个运动
- `selectedCount`：已选数量
- `currentSum`：已选卡路里总和

终止/剪枝条件

1. `selectedCount == k && currentSum == t` → **找到一个合法方案，计数+1**
2. `index == n`（用完所有运动）或 `selectedCount > k`（多选了）或 `currentSum > t`（超目标）→ **剪枝返回**

为什么叫"单递归"

整个搜索只用一个 `dfs` 函数递归往下走，通过循环（choice ∈ {选,不选}）驱动，无需多层嵌套循环。



**DFS** 是 **Depth-First Search** 的缩写，中文叫 **深度优先搜索**。

形象理解

想象你在走一个迷宫：

- **DFS** 就是：一条路走到黑，走不通了就回头，换另一条路继续走
- 它总是**先往深处走**，直到不能走了才回头

```
输入描述

思路：**最长公共子序列（LCS）**

两种情况

情况1：最后一个字符相同

```
A = "ABC", B = "ABC"
         ↑        ↑
         相同字符 'C'
```

那么：

```
dp[3][3] = dp[2][2] + 1
```

意思是：去掉最后一个相同的字符，看前面有多少公共的，再加1。

情况2：最后一个字符不同

```
A = "ABC", B = "ABD"
         ↑        ↑
         C ≠ D
```

那么：

```
dp[3][3] = max(dp[2][3], dp[3][2])
```

意思是：要么去掉A的最后一个字符，要么去掉B的最后一个字符，看哪个更大。



举例：

```
""        C   B   A   B   A   C
""    0   0   0   0   0   0   0
A     0   0   0   1   1   1   1
B     0   0   1   1   2   2   2
C     0   1   1   1   2   2   3
A     0   1   1   2   2   3   3
B     0   1   2   2   3   3   3
B     0   1   2   2   3   3   3
A     0   1   2   3   3   4   4
```

**逐行递推过程演示**

以 `A="ABCABBA"`, `B="CBABAC"` 为例：

**初始状态**

```
dp[0][*] = 0  (空字符串与任何字符串的LCS为0)
dp[*][0] = 0  (任何字符串与空字符串的LCS为0)
```

第1行 (i=1, A[0]='A')

```
j=1: A vs C → 不同 → dp[1][1] = max(dp[0][1], dp[1][0]) = max(0,0) = 0

为什么不用dfs而是用二分查找？

您问得好！让我详细解释为什么这道题更适合用**二分查找**而不是DFS：

1. 时间复杂度对比

**DFS**：需要枚举所有可能的组合

- 假设每种类型平均有M个器件，N种类型
- 时间复杂度：O(M^N)
- 示例1中：M≈2，N=3，需要尝试2³=8种组合
- 最坏情况：M=1000，N=100，需要尝试1000¹⁰⁰种组合 → **天文数字**

**二分查找**：

- 先对所有可靠性排序去重，假设有R个不同的可靠性值
- 每次验证只需O(N×M)
- 总复杂度：O(R × N × M)
- R最多100000，N最多100，M平均1000
- 约100000×100×1000 = 10¹⁰，仍然很大...

等等，让我重新算一下，其实二分查找的时间复杂度应该是：

- 二分次数：O(logR) ≈ 17次（R=100000时）
- 每次验证：O(N×M) ≈ 100×1000 = 10⁵
- 总复杂度：O(logR × N × M) ≈ 17×10⁵ = 1.7×10⁶

2. 为什么二分查找适合这道题？

**单调性**是关键：

- 如果可靠性X可行（能在预算内买到），那么任何小于X的可靠性也一定可行
- 如果可靠性X不可行，那么任何大于X的可靠性也一定不可行

```java
// 验证函数具有单调性
canAchieve(50) = true  → 可以买到可靠性≥50的器件
canAchieve(60) = true  → 可以买到可靠性≥60的器件  
canAchieve(70) = false → 买不到可靠性≥70的器件
```

3. 类比理解

想象你要找一本书的最高页数，这本书每页都有一个数字：

- **DFS**：一页一页翻，记录看到的最大数字
- **二分查找**：先猜中间页，看能不能找到，然后缩小范围

4. 什么时候用DFS？

DFS适用于：

- N很小（如N≤10）
- 需要枚举所有具体方案
- 没有单调性可用的题目

**总结**：这道题有明确的单调性（可靠性越高越难达成），所以二分查找是最优解，时间复杂度从指数级降到了对数级。
